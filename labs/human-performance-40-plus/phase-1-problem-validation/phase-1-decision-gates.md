# Phase 1 Decision Gates

[Decisión] Phase 1 ends with one primary decision. Evidence quality and contradiction determine the decision; interview count alone does not.

## `CONTINUE`

Use when one or more problems show repeated `STRONG_SIGNAL` or convergent `MODERATE_SIGNAL` across independent contexts, including concrete consequence plus behavior such as workaround, search, switching or spending.

Output: advance the supported problem to Phase 2 Solution Validation. Do not select an app automatically.

## `NARROW`

Use when meaningful problems exist but concentrate in a specific behavioral segment, training context or job-to-be-done and evidence outside it is weak or contradicted.

Output: redefine target segment/problem boundary and run a focused validation wave before broad solution work.

## `PIVOT`

Use when the assumed problems are weak or contradicted but another important, recurrent problem emerges with stronger behavioral/economic evidence.

Output: update the Research Question and hypothesis register with traceability; do not retrofit evidence to the original idea.

## `STOP`

Use when evidence remains weak, opinion-only, low-consequence or well served by alternatives, and no stronger adjacent problem emerges.

Output: close or pause the research with findings and contradictions preserved. No solution or software phase follows.

## Qualitative threshold rules

| Evidence pattern | Allowed outcome |
|---|---|
| Repeated concrete problem + consequence + active workaround/search/switching/spending | `CONTINUE` or `NARROW` |
| Strong pattern concentrated in one behavioral segment | `NARROW` |
| Original hypothesis contradicted; different problem has stronger evidence | `PIVOT` |
| Mostly preferences, feature enthusiasm or hypothetical willingness | Collect more evidence or `STOP` |
| Problems infrequent, low consequence and satisfactorily resolved | `STOP` |
| Mixed evidence with material unresolved contradictions | Additional focused research; do not force `CONTINUE` |

## Non-evidence

The following cannot validate Phase 1:

- “I like the idea.”
- “I would use an app.”
- Hypothetical feature rankings.
- Researcher/founder personal need alone.
- General market size without participant behavior.
- Interest in Movement Analysis after it is pitched.

## Future pipeline — documented, not executed

`Phase 1 Problem Validation → Phase 2 Solution Validation → Phase 3 Willingness-to-Pay → Phase 4 Minimum Sellable Product → Phase 5 Software Decision → Phase 6 MVP`

[Decisión] Movement Analysis may start a parallel technical research branch only after sufficient problem evidence and the applicable expert/sensitive-evidence gates are satisfied.
