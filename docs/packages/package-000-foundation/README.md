# Package 000 — Foundation

## Propósito

El Package 000 establece la **constitución fundacional de LabOS** como documentación. [Hecho] Este package es exclusivamente documental: no produce código de aplicación, APIs, bases de datos ni infraestructura técnica. [Hecho]

Su función es definir qué es LabOS hoy, cómo opera, bajo qué principios toma decisiones, cómo pretende generar ingresos y cuáles son los límites explícitos de su alcance actual. [Hecho] Los 16 documentos que componen este package constituyen la fuente de verdad fundacional sobre la cual se construyen todos los packages posteriores. [Hecho]

LabOS es un sistema operativo documental y metodológico para empresas de conocimiento asistidas por IA. [Hecho] En esta etapa inicial, LabOS opera con un único fundador, sin empleados, sin inversión externa y sin ingresos validados. [Hecho] El modelo de operación es documentation-first: documentar antes de construir, diseñar antes de implementar, y validar supuestos antes de escalar. [Hecho]

Este README actúa como **índice central**, **glosario autoritativo** y **declaración de estado** del package. Es el punto de entrada único para navegar los entregables del Package 000. [Hecho]

## Glosario

Definiciones canónicas de los términos de dominio utilizados en este package. Este glosario es la **fuente de verdad terminológica** — todo documento del package debe usar estos términos conforme a estas definiciones.

| Término | Definición |
|---------|-----------|
| **Package** | Unidad discreta de trabajo con entregables concretos y criterios de aceptación. Cada package tiene un conjunto definido de documentos y un estado de progreso. |
| **LabOS** | Sistema operativo documental y metodológico para empresas de conocimiento asistidas por IA. Transforma investigación en activos reutilizables y líneas de negocio. |
| **Lab** | Vertical de negocio independiente dentro del portafolio LabOS, con hipótesis de producto propia y estado de madurez definido. |
| **Activo** | Artefacto reutilizable producido por investigación o trabajo: documento, template, dataset, herramienta, componente, framework o playbook. |
| **Hipótesis** | Suposición explícita que requiere validación con evidencia antes de tratarse como hecho. Se etiqueta `[Hipótesis]` en documentos. |
| **Hecho** | Información verificada o verificable contra una fuente observable. Se etiqueta `[Hecho]` en documentos. |
| **Visión** | Aspiración a largo plazo, no comprometida ni garantizada. Se etiqueta `[Visión]` en documentos. |
| **Asset_First_Model** | Enfoque donde toda investigación (>4h acumuladas) produce al menos un activo reutilizable documentado antes de considerar productización. |
| **Revenue_Thesis** | Modelo documentado que describe cómo y por qué se espera generar ingresos, clasificado como hipótesis hasta que exista transacción real. |
| **Portfolio_Model** | Estructura organizativa donde múltiples labs operan bajo infraestructura compartida de LabOS con reglas de priorización definidas. |
| **Clasificación_Epistémica** | Sistema de etiquetado que diferencia hechos, hipótesis, visiones y decisiones en cada documento del package. |
| **Package_Foundation** | Este package (000): conjunto de 16 documentos que constituyen la definición fundacional de LabOS. |
| **Fundador** | Persona que opera LabOS en esta etapa inicial; único stakeholder con capacidad de decisión y ejecución. |
