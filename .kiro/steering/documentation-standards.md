# Documentation Standards — LabOS

## Idioma

- Idioma principal de documentación: **español**.
- Nombres de archivos, carpetas, variables y código: **inglés**.
- Términos técnicos sin traducción forzada (e.g., "package", "blueprint", "spec").

## Formato

- Markdown profesional con estructura clara (headers, listas, tablas).
- Un documento = un propósito. No mezclar temas no relacionados.
- Máximo un nivel de anidación para carpetas de documentación antes de replantearse la estructura.

## Clasificación de contenido

Todo contenido debe indicar explícitamente su naturaleza:

| Etiqueta | Significado |
|----------|-------------|
| **Hecho** | Información verificada o verificable |
| **Hipótesis** | Suposición por validar |
| **Visión** | Aspiración a largo plazo, no comprometida |
| **Decisión** | Elección tomada con contexto y fecha |

## Prohibiciones

- No inventar clientes, ingresos o validación que no exista.
- No presentar hipótesis como hechos.
- No documentar funcionalidad que no existe como si estuviera implementada.
- No usar lenguaje de marketing interno (e.g., "revolucionario", "disruptivo") sin evidencia.

## Documentación como producto

La documentación no es un subproducto: es parte del entregable. Todo package debe incluir documentación actualizada antes de considerarse completo.
